## Definition of 'MVP ready; AI plug-in pending'
- Every P0 route usable with keyboard/mobile; no dead ends or inert buttons.
- Data can be created, read, updated where appropriate, and correctly scoped to user in Supabase; RLS tested across two accounts.
- The NeuroPrevent flow and NeuroRecovery flow run end-to-end using **clearly labeled synthetic fixture output** at the AI integration boundary; deterministic non-AI steps are real.
- All AI modules have versioned, validated input/output contracts; swap fixture adapter for remote adapter via server-only config; no UI changes required.
- Emergency symptom routing works even if AI is unavailable; no fabricated clinical risk or diagnostic claims.
- Loading, offline, error, empty, denied-permission and retry states are implemented.
- `npm run lint`, `npx tsc --noEmit`, `npm test`, `npm run build` pass; feature integration and usability checks documented.
- Known limitations disclosed; P1/P2 not presented as fully implemented without evidence.

## Scope clarifier
**P0 = product-complete without AI live service.** An AI feature is 'integration-ready' if its UI, input handling, fixture adapter, endpoint contract, success/error states, and tests are complete; it is **not** 'fully integrated' until the live service passes acceptance tests. F03/F06 are P1; F09–F11 are P2 unless team changes priority.
